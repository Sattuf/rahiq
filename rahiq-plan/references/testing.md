# الاختبار وقوائم الفحص (Testing & Gates)

## 1. الهرم

| النوع | الأداة | يغطي |
|---|---|---|
| وحدة المجال | xUnit | Money، الحجز، آلة حالات الطلب، توزيع الخصم، FEFO، قواعد التحذيرات |
| البنية | NetArchTest | حدود الوحدات والطبقات |
| التكامل | WebApplicationFactory + Testcontainers (PostgreSQL، Redis، Meilisearch) | الـ API كاملًا بقاعدة بيانات حقيقية |
| **التجارة** | مجموعة مخصصة (إلزامية) | التزامن، webhooks، المبالغ، الحجز |
| عقود المزودين | خوادم وهمية (WireMock) بسلوك المزود الحقيقي + Sandbox | الدفع، الشحن، الفاتورة |
| الواجهة | Vitest + Testing Library | المكوّنات والحسابات في الواجهة |
| من الطرف للطرف | Playwright بكل لغة | الرحلات الحرجة |
| الأداء | Lighthouse CI + k6 | الميزانيات والحمل |
| الأمان | ZAP، gitleaks، فحص التبعيات | الثغرات الشائعة |

## 2. مجموعة التجارة (GATE المرحلة 7)

كل اختبار هنا يعمل على PostgreSQL حقيقي:

1. **البيع الزائد:** 3 قطع في المخزون، 50 عملية دفع متزامنة لقطعة واحدة ← 3 طلبات مؤكدة بالضبط، 47 رسالة "نفد"، و `qty_on_hand = 0`، ولا قيمة سالبة.
2. **الحجز المنتهي:** حجز ثم انتظار انتهاء المهلة ← عامل التحرير يعيد الكمية، والطلب يُلغى.
3. **Webhook مكرر:** نفس الحدث 5 مرات ← طلب مؤكد واحد، فاتورة واحدة، بريد واحد.
4. **Webhook مزور:** توقيع خاطئ ← 401 بلا أي تغيير.
5. **مبلغ غير مطابق:** إشعار نجاح بمبلغ أقل ← الطلب لا يتأكد، وتنبيه.
6. **نجاح بعد انتهاء الحجز:** المخزون متاح ← يكتمل. غير متاح ← استرداد آلي + تنبيه.
7. **النقر المزدوج على "ادفع":** نفس Idempotency-Key ← طلب واحد.
8. **الحسابات:** 1000 سلة عشوائية (أسعار، كميات، قسائم، شحن) ← `total = subtotal - discount + shipping` دائمًا، ومجموع خصومات الأسطر = خصم الطلب، ومجموع الضرائب صحيح حتى آخر قرش.
9. **القسيمة المحدودة:** `max_uses = 10`، و 30 طلبًا متزامنًا بها ← 10 فقط.
10. **FEFO:** دفعتان بتاريخين ← الأقدم انتهاءً تُصرف أولًا، والقريبة جدًا من الانتهاء لا تُصرف.
11. **اللقطة المجمدة:** تغيير اسم المنتج وسعره بعد الطلب ← الطلب والفاتورة كما كانا.
12. **سعر الخصم القانوني:** تاريخ أسعار معروف ← "السعر السابق" المعروض = أدنى سعر خلال 30 يومًا.

## 3. رحلات Playwright

1. عطر: الرئيسية ← عالم العطور ← فلتر ← منتج ← عيّنة + قارورة ← سلة ← دفع بطاقة (Sandbox) ← صفحة النجاح ← بريد.
2. عسل: عالم العسل ← منتج ← بطاقة الدفعة ← سلة ← دفع عند الاستلام.
3. صندوق هدايا لعنوان آخر مع رسالة وإخفاء السعر.
4. دليل العطور حتى الإضافة للسلة.
5. مسح QR (فتح رابط الدفعة) ← صفحة الدفعة.
6. زبون عائد: تسجيل دخول برمز ← إعادة طلب.
7. إرجاع: طلب ← حالة سطر غير قابل للإرجاع ← مسار "وصل تالفًا".
8. الإدارة: دفعة جديدة ← منتج ← نشر (مع محاولة كلمة ممنوعة تُمنع) ← طلب ← تجهيز ← شحن.

## 4. الفحص الذاتي للواجهة

1. لقطات بـ 1440×900، 1280×800، 390×844، 375×667، بكل لغة.
2. كل زر ورابط ونموذج، وحالات الخطأ والفراغ والنجاح مصممة.
3. البابان، رحلة النوتات، السكب البطيء: تمرير بطيء ثم سريع ثم عكسي. لا تقطّع.
4. Lighthouse على هاتف محاكى: أداء 90+، وصولية 100، SEO 100. ثم هاتف حقيقي عبر 4G.
5. الحركة المخفضة قبل التحميل، ثم أثناءه.
6. بلا WebGL: الموقع كامل وجميل.
7. صفحة الدفع: بلا أي مكتبة ثلاثي أبعاد أو شيدر في الحزمة (تحقق من تقرير الحزم).
8. لا تمرير أفقي في RTL وعلى الهاتف.
9. وحدة التحكم خالية من الأخطاء.
10. منتج بلا صورة ثانية، اسم تركي طويل بحروف خاصة، خلطة بخمسة مكونات، عطر بلا نوتات قاعدية: كلها تبدو مقصودة.
11. التحذيرات ظاهرة في كل منتج يستحقها، بكل لغة.
12. **النظرة الجديدة أخيرًا:** كزائر لأول مرة، هل يبدو القسمان علامة واحدة؟ هل هناك شيء يبدو حشوًا أو قالبًا عامًا؟
