# التشغيل والنشر (DevOps)

## 1. البيئات
Local (docker compose) ← CI (حاويات مؤقتة) ← Staging (Sandbox لكل المزودين) ← Production.

## 2. الاستضافة (بداية معقولة)
- **خادم تطبيق (VPS):** Docker Compose: API (نسختان)، Next.js (نسختان)، Worker، Redis، Meilisearch، و Caddy كوكيل عكسي مع HTTPS تلقائي.
- **قاعدة البيانات:** PostgreSQL مُدار إن أمكن (أقل عبئًا)، أو على خادم منفصل مع pgBackRest.
- **Cloudflare:** DNS، CDN، WAF، Turnstile، و **R2** للصور والتقارير (بلا رسوم خروج).
- موقع الخوادم: قرار مع المحامي حسب KVKK (compliance.md).
- المراقبة: Seq أو Grafana (Loki، Tempo، Prometheus) + OpenTelemetry + Sentry للواجهة + مراقبة توفر خارجية.

## 3. CI/CD (GitHub Actions)
- كل PR: build، lint، format، اختبارات الوحدة والبنية، التكامل ومجموعة التجارة (Testcontainers)، فحص مفاتيح الترجمة، Playwright المختصر، gitleaks، فحص التبعيات.
- الدمج إلى `main`: بناء الصور موسومة بالـ SHA ← نشر Staging (الترحيلات أولًا) ← Playwright الكامل + Lighthouse CI ← موافقة يدوية ← الإنتاج بنشر متدرج مع فحص `/health/ready`.
- التراجع بأمر واحد، موثّق ومجرّب.
- **تجميد النشر في ذروة المواسم:** لا نشر للميزات في آخر أسبوع قبل العيد. إصلاحات عاجلة فقط.

## 4. التنبيهات
- أخطاء 5xx فوق 1% لخمس دقائق.
- **فشل الدفع فوق النسبة المعتادة** (قد يعني عطلًا لدى المزود أو في التكامل).
- webhook لم يصل لطلب معلق منذ أكثر من 30 دقيقة.
- فرق في المطابقة اليومية.
- فشل إصدار الفاتورة بعد إعادة المحاولات.
- Outbox متأخر، القرص فوق 80%، فشل النسخ الاحتياطي.

## 5. النسخ الاحتياطي
PostgreSQL: كامل يومي + WAL (استعادة لنقطة زمنية 14 يومًا). R2 بإصدارات. RPO أقل من 15 دقيقة، RTO أقل من ساعتين. **اختبار الاستعادة شهريًا.** بيانات الطلبات مال الناس وسجل ضريبي: فقدانها ليس خيارًا.

## 6. الإطلاق
1. إطلاق ناعم لدائرة صغيرة (50 إلى 100 شخص) مع قسيمة شكر، لأسبوعين. راقب كل طلب بعينك.
2. إصلاحات بالأولوية: ما يمنع الشراء، ثم ما يربك، ثم ما يزعج.
3. إطلاق عام قبل موسم الهدايا بستة أسابيع على الأقل.
