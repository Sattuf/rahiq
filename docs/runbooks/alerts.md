# التنبيهات وما تفعله عند كل واحد (devops.md §4)

| التنبيه | المصدر | الإجراء الأول |
|---|---|---|
| 5xx فوق 1% لخمس دقائق | Seq أو Grafana على سجلات API | افحص `/health/ready`، وآخر نشر. إن بدأ مع النشر: `infra/scripts/deploy.sh --rollback` |
| فشل الدفع فوق المعتاد | سجلات Payments | افحص صفحة حالة iyzico. لا تغيّر الكود أثناء عطل المزود |
| webhook لم يصل لطلب معلق منذ 30 دقيقة | العامل المتكرر | ابحث الطلب في لوحة iyzico. المطابقة اليومية تصحح الحالة، وإن احتاج الأمر تدخلًا فبيد المدير |
| فرق في المطابقة اليومية | بريد إلى `StaffAlertRecipients` | قارن الطلب بالمبلغ عند المزود قرشًا بقرش. لا استرداد يدوي قبل الفهم |
| فشل إصدار الفاتورة بعد إعادة المحاولات | Documents | افحص حساب مزود e-Arşiv. الطلب لا يُشحن بلا فاتورة |
| Outbox متأخر | `infra.outbox` | هل العامل يعمل؟ `docker compose ... ps worker`. للتفريغ اليدوي: `dotnet Rahiq.Api.dll drain-outbox` |
| مخزون منخفض، أو دفعة تقترب من الانتهاء | `StockLow`، `BatchNearExpiry` | للمدير: إعادة الطلب، أو تخفيض سعر الدفعة قبل 60 يومًا من انتهائها |
| القرص فوق 80%، أو فشل النسخ الاحتياطي | مراقبة الخادم، و `backup-drill.yml` | النسخ الاحتياطي أولوية قصوى: [restore.md](restore.md) |

**اختبار التنبيهات قبل الإطلاق (GATE 10):** اصطنع كل حالة مرة واحدة على Staging، مثل webhook بمبلغ خاطئ أو إيقاف العامل، وسجّل أن التنبيه وصل.
